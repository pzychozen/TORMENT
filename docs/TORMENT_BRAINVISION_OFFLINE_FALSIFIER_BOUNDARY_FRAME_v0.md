## 4. Hard requirements

**Isolation from the service.** No imports from `torment_service/`, including `torment_service/kernel/`.

**Outputs.** Outputs are only non-authoritative research artifacts: metrics, tables, plots, confusion
matrices, scores, offline labels, diagnostic traces, **offline research logs and local result summaries outside TORMENT memory, canon, substrate, or runtime state**.

**Math.** Service-disconnected math only; pure spectral equations re-derived in an offline namespace; no
authority-bearing outputs.

## 5. Safe metric language

"Event detection" language is avoided. A future falsifier describes what it measures using
non-authorizing terms only:

- offline event-label separability
- offline descriptor-class discrimination
- continuity/disruption separability
- descriptor-regime classification
- non-authorizing diagnostic score

## 6. Required baselines

A future falsifier's predeclared metrics must be tested against explicit baselines, including:

- frame-diff
- descriptor-only classifier
- plain luminance / RGB / statistical baseline
- random mapping
- shuffled-label baseline
- phase / time-shuffled control
- the old `visual_bus_v0` fixed mapping, as a failed / negative baseline reference where available

the falsifier at boundary level; it does not authorize adding runtime inputs, live surfaces, or new
