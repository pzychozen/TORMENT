# TORMENT Gate A — Pre-Mechanics Dependency Decision Frame v0.1

## 0. Non-authorization statement

This is a **pre-mechanics dependency decision frame** — a map of which *design-only*
question, if any, the operator may authorize before any Gate A wall mechanics
could ever be considered. It is **not mechanics and not implementation.**

- No lane is selected.
- No mechanics are authorized.
- No producer, candidate store, admission, or promotion is authorized or
  implemented.
- No runtime is authorized.
- No default next step exists.
- Gate A remains **paused**.
- Gate D / private cognition remains **parked**.
- Every question below is **design-only** and requires a **separate operator
  decision plus Codex review** before any artifact or patch.

This artifact may shape context. It must not seize authority.

## 1. Current phase boundary

`[FACT]` Gate A's wall currently holds **by absence / unwired topology, not by a
mechanism**: no live unadmitted-candidate producer exists, so nothing is produced
that could reach the ordinary ingest fan-out root. This is not tag filtering, not a
candidate store, and not admission/promotion mechanics.

`[FACT]` The preflight finding being acted on: **do not bundle Gate A mechanics
with producer / store / admission authorization.** Those are distinct decisions on
a dependency stack (§3); collapsing them into one "authorize mechanics" step would
hide several operator forks inside one.

## 2. Doctrine filter

Every layer and question is read under, and must preserve:

> Memory may shape context. Memory may not seize authority.
> Audit observes authority. Audit must not become authority.

A layer that could only proceed by violating this filter is **gated** by
definition.

## 3. The dependency stack (split; each layer separately authorized)

The path toward a real wall is a **stack of separate decisions**, in dependency
order. Authorizing one layer does **not** authorize the next; each is its own
operator decision plus Codex review. Layers 1–3 are **design-only** (docs); layers
4–5 are **later and separately authorized** and are **out of scope for this
frame's questions**.

1. **Producer-shaped contract — design-only, no runtime.** A requirement-level
   description of what an unadmitted-candidate producer would be (shape,
   obligations), with **no producer built, no chamber, no runtime.**
2. **Seam-selection — design-only, no code.** A comparison of where the wall could live (producer-side boundary / ingest-entry gate /
   writer-authority gate / inspection surface), **selecting nothing and writing no
   code.**
3. **Candidate boundary / admission requirements — design-only, no store, no
   admission implementation.** Requirement-level statement of the boundary and the
   admission obligations (≤ released/low-authority; admission ≠ promotion), **with
   no candidate store and no admission/promotion mechanics built.**
4. **Runtime mechanics — later, separate authorization.** The actual wall
   mechanism. **Not on the table here.**
5. **Gate D / private cognition — later, separate authorization.** The inhabitant
   the wall would protect. **Not on the table here.**

Dependency note: layers 4 and 5 presuppose 1–3; this frame deliberately does not
reach them.

## 4. Operator decision questions (only these)

Posed as questions only (decision-ready as questions; nothing is chosen here). The
operator is asked to choose among **design-only** steps or to hold:

1. **Authorize a design-only producer-shaped contract?** (Layer 1 — docs only; no
   runtime, no producer, no chamber.)
2. **Authorize a design-only seam-selection comparison?** (Layer 2 — docs only;
   selects no seam, writes no code.)
3. **Authorize design-only candidate boundary / admission requirements?** (Layer 3
   — docs only; no candidate store, no admission/promotion implementation.)
4. **Keep Gate A paused?** (Take none of 1–3 now.)

These four are the entire decision surface of this frame. Runtime mechanics
(layer 4) and Gate D (layer 5) are **not** questions here and would each require
their own separate authorization later.

## 5. Preserved facts

- **Gate A currently holds by absence / unwired topology, not by mechanism**
  (§1). Any of layers 1–3 would change only *design documents*, not that runtime
  fact.
- **Seam B (`TormentFabric.ingest`) is the grounded downstream chokepoint** — the
  ingest fan-out root is identified and there is no current exclusion-tag gate to
  unlearn — **but it is not sufficient alone**: a chokepoint with nothing upstream
  to gate (no producer) does not constitute a wall, and seam-selection (layer 2)
  is **not** decided here.
- **The producer-shaped contract (layer 1) may be the first design question** in
  the stack, **but it is not selected here** — naming it first in dependency order
  is not choosing it; the operator may equally choose layer 2, layer 3, or to keep
  Gate A paused.

## 6. Forbidden crossings / what this frame does not do

This frame neither crosses nor softens, and does not authorize by implication, any of:
wall mechanics; candidate store; governed admission; promotion crossing; Gate D
runtime; Envelope Audit runtime; private-owner live wiring; Shape B; writer fixes;
P4 O1/O2 mechanics; Seed-Gov mechanics; endpoint/schema/API changes; prompt
exposure; AgentRunner ownership expansion; retrieval feedback; persistence;
autonomy; audit-to-control feedback; database/substrate mechanics; carrier/schema/
field selection; runtime of any kind.

It does **not** normalize, fix, or reclassify the parked writer non-conformances
(`gravity_correction` canon=True, `_maybe_emit_identity_anchor`, `/promote` force,
`mood_drift → canon`); they remain **known-parked context only**, outside this
frame's authority.

It creates no code, no tests, no §0 pointer, and no other docs.
