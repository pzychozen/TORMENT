# Troubleshooting

TORMENT v2.1

## 1) "My embedder isn't working"
Call `GET /embedder/check`. If degraded mode is active, install missing deps (e.g., `sentence-transformers`), check Ollama URL/model, or set `TORMENT_EMBED_STRICT=1` for fail-fast.

## 2) "Embedding dimension mismatch (409)"
A workspace locks its embedding dimension once used. Fix: create a new workspace, or use `/workspace/clone` to migrate under the new embedder.

## 3) "Memory feels noisy / irrelevant"
Try reducing `top_k`, reducing `TORMENT_THREAD_WINDOW_BONUS`, disabling bridge peeking, or using `continuity_debug=true` to see which bonus is dominating.

## 4) "Anchors feel wrong / too many"
Increase `TORMENT_ID_ANCHOR_MIN_COUNT` and `TORMENT_ID_ANCHOR_MIN_GAP_STEPS`. Or disable anchors with `TORMENT_ID_ANCHOR_ENABLE=0`.

## 5) "I changed summaries but retrieval didn't change"
Run `POST /workspace/repair_embeddings` with `mode="scan"` then `mode="repair"`. Checksums detect drift and will re-embed stale entries.

## 5b) "Repair/clone is taking a long time"
Use the async job endpoints: `POST /workspace/repair_embeddings/job` to start, `GET /workspace/repair_embeddings/job/{job_id}` to check progress, `POST /workspace/repair_embeddings/job/{job_id}/cancel` to stop.

## 6) "How do I know what settings are active?"
`GET /config` shows effective config with sources. `GET /health` for high level. `GET /profiles` for presets.

## 7) "Character doesn't feel like the seed" (v2.0)
With hash embeddings, seed concepts produce orthogonal vectors so they don't cluster naturally. Switch to real embeddings (`st` or `ollama` provider) for proper semantic clustering. The character still functions with hash embeddings, but the seed basin won't have natural thematic coherence.

## 8) "Character feels too rigid / won't evolve" (v2.0)
Lower `TORMENT_CHARACTER_CORRECTION_THRESHOLD` (default 0.35) to let the character drift more before gravity correction fires. Or raise the value if you want a looser character.

## 9) "Character drifts too far from seed" (v2.0)
Increase `TORMENT_CHARACTER_GRAVITY_STRENGTH` (default 0.12) for stronger pull back to seed. Also check that your seed text is specific enough — vague seeds create shallow basins.

## 10) "Don't want character features"
Set `TORMENT_CHARACTER_ENABLE=0`. The system reverts to plain memory-only behavior.

## 11) "Compression isn't firing" (v2.1)
First check `TORMENT_COMPRESS_ENABLE=1`. Compression only fires at corridor transition events (corridor exit, cycle stage change, emergency tear). If the kernel stays stable without any corridor transitions, compression won't trigger — this is by design. Also check `TORMENT_COMPRESS_MIN_STEP` (compression is disabled before this step) and that memories are old enough to be eligible (`TORMENT_COMPRESS_MIN_AGE`).

## 12) "Too many memories disappearing" (v2.1)
Compression never deletes memories — short-path reduces strength (fading), long-path exports to deep store. If memories feel "gone", they may have faded below retrieval threshold. Check: are the lost memories canon? (Canon is never compressed.) Are they core_identity tier? (Protected.) Raise `TORMENT_COMPRESS_MIN_AGE` to protect younger memories.

## 13) "Spirit return feels generic / same voice every time" (v2.1)
Check which return mode is firing: look for `spirit_return_mode` in query results. Resonance (the most distinctive mode) requires the deep memory's birth symbol to match the current kernel symbol AND high warmth. If all returns are "recollection" (the default), it means warmth is low (memories haven't been retrieved enough times) or no symbol interaction rule matches for resonance.

## 14) "Spirit return warmup not accumulating" (v2.1)
The WarmupTracker persists to a JSONL file in the agent's warmup directory. Check that the file exists and is writable. Warmth increments only count retrievals within a 200-step window — if the gap between retrievals is too large, warmth may have decayed. Also verify that deep store queries are actually returning results (`TORMENT_COMPRESS_ENABLE=1` is required).

## 15) "Phase durations all show 0" (v2.1)
PhaseTimer initializes on first ingest. If all `phase_duration_steps` show 0, check that `tri_mod` is being passed to ingest (it's auto-generated by `kernel.process()`) and that `cycle_stage` is present in tri_mod. The timer resets on phase transitions, so rapid cycle stage changes can produce short durations.

## 16) "Tests failing after changes" (v2.1)
Run the full suite: `python -m unittest discover -s tests -v`. The 4 import errors (test_embed_dim_lock, test_embedding_store, test_golden_emergent, test_smoke_api) are expected in environments without fastapi/pytest — they are not regressions. The 185 unittest-based tests should all pass.

## Unified maintenance endpoint
If you want a single entry point: `POST /workspace/maintenance` (sync) or `POST /workspace/maintenance/job` (async). Use `mode=scan_embeddings` or `mode=repair_embeddings`.
