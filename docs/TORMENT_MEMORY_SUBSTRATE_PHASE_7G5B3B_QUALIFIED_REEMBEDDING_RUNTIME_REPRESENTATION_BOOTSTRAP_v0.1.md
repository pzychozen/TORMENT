# TORMENT Memory Substrate — Phase 7G5B3B

## Qualified re-embedding runtime representation bootstrap

Phase 7G5B3B adds a narrow, STAGING-only administrative service:

```text
NativeMigrationRuntimeReembeddingBootstrapService
    .bootstrap_from_qualified_text(..., embedder=caller_owned_embedder)
```

It is deliberately distinct from 7G5B3A:

```text
B3A: BYTE_DERIVATION_POSSIBLE
     -> exact frozen legacy capture bytes

B3B: REEMBED_REQUIRED | NO_VECTOR_PRESENT | UNUSABLE_VECTOR_EVIDENCE
     -> one caller-owned target-embedder observation of qualified B2 R2 text
```

`BYTE_DERIVATION_POSSIBLE` is refused with
`B3A_DETERMINISTIC_CAPTURE_BOOTSTRAP_AVAILABLE`, before model contact.

## Preconditions and ownership

The request contains references only: snapshot, namespaced EID, exact R1/R2,
scope plans, target lane, and idempotency identity. It never accepts caller
vector bytes. The embedder is passed explicitly by the administrative caller.
This service does not construct an embedder, read provider configuration or
credentials, choose a fallback provider, or call `build_embedder_from_env()`.

Before `embedder.embed()` it proves:

- schema v1.2; STAGING core; `LEGACY_ACTIVE` deployment with no referenced core;
- verified persisted snapshot and canonical source EID/runtime order facts;
- the exact B3A-strength B2 R1 -> R2 operation, transition, effect, output,
  governance, provenance, lifecycle, and `NOT_APPLICABLE` authority topology;
- B1 scope-plan/readiness evidence and an accepted B3B strategy;
- exact target lane `COMPAT_EMBEDDING/1/compat-embedding-v1/RAW_VECTOR/float32`;
- exact caller embedder `provider`, `model`, and `dim` equality with that lane;
- no competing current target representation.

An already-READY exact B3B result is recovered through
`NativeCompatEmbeddingReader` with zero model calls. Any other existing target
representation fails closed.

## Canonical input and generated bytes

Both B3A and B3B share one frozen text selection rule:

```text
R2 payload.summary
otherwise R2 payload.text
```

The selected field and exact canonical field/value digest are bound in the
administrative intent. B3B calls the supplied embedder exactly as normal Fabric
ingestion does:

```python
np.asarray(embedder.embed(text), dtype=np.float32).reshape(-1)
```

It requires the target dimension and finite values. No prefix, normalization,
rescaling, rounding beyond float32 conversion, zero-vector substitution, or
fallback provider is added. The RAW float32 payload SHA-256 is the vector
integrity value; it is separate from an input/provider/model audit digest.

## Publication and recovery

For a successful fresh observation B3B creates exactly one representation on
the current B2 R2 and uses the native semantic helpers:

```text
CREATE_REPRESENTATION_PENDING
-> ESTABLISH_REPRESENTATION_INTEGRITY_EXPECTATION (SHA256 / RAW)
-> PUBLISH_REPRESENTATION_READY (READY / USABLE / selected MATCH)
```

The marker-protected prepared plan binds the core, snapshot, namespace, object,
EID, R1/R2, B2 witnesses, runtime order, scope-plan digest, canonical input
field/digest, target lane, caller embedder identity, B1 strategy, retained
legacy capture IDs, idempotency namespace, and stable representation identity.
The first observed payload hash is additionally recorded in the PENDING
administrative intent. It is an observation witness, not legacy evidence.

The retry boundary is explicit:

- before PENDING, embedder failure leaves no B3B representation publication;
- after PENDING but before expectation, retry revalidates and calls the
  embedder again, so its new output may establish the first expectation;
- after expectation, retry calls the embedder again and requires byte-identical
  SHA-256 output. A different result fails closed with
  `B3B_REEMBED_OUTPUT_NOT_BYTE_STABLE` and never overwrites the expectation;
- after READY, the reader witness is recovered without another model call.

## Deliberate non-effects

B3B creates no object revision or R3 and does not alter R2 payload JSON,
including legacy `embedding_provider`, `embedding_model`, `embedding_dim`, or
`embedding_checksum` fields. Native runtime identity remains in the qualified
representation carrier. Legacy captures, including unusable or mismatched ones,
remain unchanged retained evidence; no capture is invented for a no-vector
source.

It changes no EID aliases, runtime order, governance, provenance, lifecycle,
authority, motifs, or side stores. It adds no schema and does not activate
native Fabric routing, dual write, dual read, or cutover.

`LEGACY_PAYLOAD_EMBEDDING_METADATA_PARITY = DEFERRED_NOT_RUNTIME_BLOCKING`.
