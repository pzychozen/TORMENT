## §8 Four distinctions

- **Memory as context source:** inert material — retrieved, governed, labeled, bounded. Its legitimate ceiling is *being available*.
- **Caller as authority-bearing act:** the decision that *this* context reaches *this* generation *now*. This act exercises real authority; the requirement is that the authority be **visible, bounded, and non-inheritable** — not that it be pretended away.
- **Prompt assembly as possible authority seam:** selection, ordering, labeling, and truncation are each a small editorial power; unseen editing is the subtlest control surface in the system. The seam must be capturable and auditable (the exact prompt-request carry-through work proved the observation shape; it is cited as evidence, not wiring).
- **Model output as non-authorizing:** nothing the model says grants, requests, or escalates access. **Output is voice, never key.** An output that asks for memory is a request to the operator's gates, not to the fabric.

## §9 Likely leak paths — named so any future artifact must guard them

- **Retrieved context becoming instruction** — context rendered imperatively, or unlabeled, reads as command.
- **Salience/confidence becoming prompt priority** — fabric-internal scalars silently ordering the prompt; numeric guidance becoming positional authority.
- **Prior artifact becoming caller authority** — a citation chain read as standing permission (the H3 lesson's read-side twin).
- **M3 direction becoming trajectory** — caller study cited as evidence a live surface is due.
- **Operator preference becoming hidden mandate** — leanings encoded in assembly defaults nobody can see; the operator's own power requires the same visibility discipline as force.
- **Model output requesting memory access** — voice becoming key.
- **Memory selection becoming identity pressure** — what is chosen for the prompt quietly defining who the inhabitant is; selection as soft canon.
- **Prompt assembly becoming unseen control** — the seam editing without capture.

## §10 Required invariants — what any future answer must satisfy

1. **Context is not command.** Governed memory enters generation as labeled, bounded, non-imperative material, always distinguishable from instruction.
2. **Caller authority must be visible, bounded, and non-inheritable.** The act of calling is owned, witnessed, scoped to the turn, and confers nothing on later turns, artifacts, or components.
3. **Prompt assembly must be capturable and auditable.** The exact rendered, model-visible context must be observable at the boundary — no unseen editing.
4. **The generating side may not self-select memory context.** Whatever generates does not choose what it is shown; selection and generation are separated powers.
5. **Model output is voice, never key.** No output grants, requests, or escalates memory access, caller status, or any authority.
6. **Retrieved memory must not become instruction by formatting, ordering, salience, confidence, or hidden labels.** No delivery detail may smuggle imperative force.
7. **Whoever selects context shapes the inhabitant, and shaping must never masquerade as remembering.** Context selection is a visible, contestable, editorially-owned act — never presented as the neutral fact of what the fabric contains.

## §12 Relation to MCP/action/model-body movement — without opening them

A caller owns *context into generation*, never *generation into action*. No caller-owner may double as an action dispatcher; nothing assembled into a prompt may constitute an action instruction to MCP or any body/movement surface; and action-side urgency may never justify caller-side shortcuts (the backward-pressure clause, read-side edition). MCP stays read/advisory/reactive; movement stays a scene-disjoint render sink. Stating this closes a future confusion and opens nothing.
