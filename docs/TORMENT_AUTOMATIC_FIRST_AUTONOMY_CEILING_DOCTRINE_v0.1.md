# TORMENT — Automatic-First / Autonomy Ceiling Doctrine v0.1

**Status:** DOCS-ONLY doctrine / operator decision record. **Non-authorizing, non-implementing. Opens no
implementation lane.** Records the posture that TORMENT is **automatic-first now**, with **autonomy as a
separately-gated future option** — not a default, not implied, not opened. This is the **Surface 3
(autonomy)** posture of the Live-Power Doctrine, and the decision the Typed Embodiment Tunnels and
External-Model-First docs both defer to. `PROJECT_ORIENTATION_MAP.md` §0 remains the active work-order; §0
wins unless Hilmir explicitly overrides.

**Decision (carried, exact):**

> **TORMENT is automatic-first. Automatic, reactive behavior is the sufficient default. Autonomy — acting
> without a direct operator request or current triggering input — is not the default, is never implied, and
> is not opened. The ceiling remains memory/context floor + Mode 0.**

---

## 1. Purpose

To fix the line between **automatic** and **autonomous** operation before any future model, embodiment, or
Dream work could blur it, and to record that TORMENT stays automatic-first. This is the keystone the other
live-power docs point at: whenever they say "a separate autonomy gate," they mean *this* posture.

## 2. Decision

- **TORMENT is automatic-first now.**
- **Automatic / reactive behavior is the sufficient default** — it covers the intended capability without
  autonomy.
- **Autonomy is not the default, is not implied by any other surface, and is not opened here.**

## 3. Definitions — the distinction (make this unmissable)

- **Automatic** = **reactive**. TORMENT acts **only within currently authorized surfaces** and only in response to
  an operator/user input, an explicit invocation, or a **bounded external event**: a current, finite,
  operator-admitted event delivered to an already-open reactive surface. A bounded external event is **not** a
  scheduler, timer, polling loop, background watcher, ambient sensor stream, model self-continuation, durable
  subscription, or standing trigger. Each action is *triggered from outside*. When there is no current
  input/event, there is no generation, action, memory, scheduling, Dream, MCP/tool, or non-render work.
  **Automatic is the current posture, and it is enough.**
- **Autonomy** = **self-initiating**. TORMENT begins work **without a direct operator request or current
  triggering input** — including generation, action, memory work, scheduling, background watching,
  self-directed consolidation, idle navigation, unsolicited interaction, and any sensorimotor /
  perception-to-action loop. Autonomy is the ability to *start on its own*.

**The single test:** *did something outside TORMENT trigger this action right now?* If yes → automatic
(allowed). If no → autonomy (closed, separately gated). Responding only when there is input is automatic and
sufficient; doing things when there is no input is autonomy and is not opened.

## 4. Current ceiling

**Mode 0 / automatic-only, reaffirmed.** The ceiling remains **memory/context floor + Mode 0**. Nothing in
TORMENT initiates work on its own today, and this doctrine keeps it that way.

## 5. Future autonomy (named, not opened)

Autonomy may only ever be considered later as an **explicit, operator-owned mode ladder** (Mode 0 → higher
modes). **Each higher mode is a separate gate requiring Codex challenge and an explicit operator decision.**
The modes are named here only to fix that they are gated and sequential — none is opened, sketched into
mechanics, or made automatic-next. Autonomy is a deliberate switch the operator may one day flip, never a
default the system drifts into.

## 6. Relation to the Live-Power Doctrine

This records the **Surface 3 (autonomy)** posture. **No surface authorizes another**, and **automatic
behavior authorizes no autonomy by implication** — reacting to input, however richly, never becomes
self-initiation.

## 7. Relation to Typed Embodiment Tunnels

**Tunnel permission is not loop permission.** Embodiment expression and autonomic body-liveness are
**render-only presentation, not autonomy**, when confined to procedural/current-input-bound self-presentation
with no task, memory, tool, scheduling, model, or world-state effect. **Any perception-to-action loop, idle
navigation, or sensorimotor policy is a separate autonomy-mode gate**, never granted by holding tunnels.

## 8. Relation to External-Model-First

An **external / edge model call does not grant a live loop.** Model output does **not** authorize
self-triggering, continuation, scheduling, tool action, or idle agency. **Who closes the loop, and whether
it runs unprompted, is the autonomy decision** — separate from, and not implied by, calling a model.

## 9. Relation to Dream

Any future "dreaming" remains **externally triggered, bounded, and inert-candidate-producing** unless a
separate gate says otherwise. **No self-initiating Dream / runtime loop, no self-trigger, no self-budget.**
If a future Dream lane is separately authorized, an externally triggered Dream turn would be automatic in
form; self-starting dreaming is autonomy and stays closed. This authorizes no Dream producer, chamber,
scheduler, runtime, or candidate material now.

## 10. Relation to MCP / action

MCP remains **read / advisory / reactive** unless separately gated. **No generic MCP / tool action is
opened.** A reactive memory surface is automatic; a self-directed action agent is autonomy.

## 11. Closed axes preserved

No durable write; no final-output / finalizer / refusal authority; no identity / canon / personhood
authority; no substrate / admission mechanics. This doctrine grants none of them and lifts no earlier fence.

## 12. Allowed-now / frameable-later / HOLD

| Posture | Items |
|---|---|
| **Allowed now** | Automatic / reactive behavior within currently authorized surfaces only — respond to operator/user input, explicit invocation, or bounded external event as defined in §3; memory/context retrieval; context/retrieval shaping only; audit/observability/advisory; MCP as read/advisory memory surface; **Mode 0** |

*"Frameable later" means a future separate gate may frame it; **framing is not authorization**.*

## 13. This opens no implementation lane

Decision framing only. No code, tests, implementation, runtime, provider wiring, prompt path, scheduler /

**Verdict: AUTOMATIC-FIRST RECORDED — AUTOMATIC IS THE SUFFICIENT DEFAULT / AUTONOMY IS CLOSED AND
SEPARATELY GATED / MODE 0 REAFFIRMED / NO SURFACE AUTHORIZES AUTONOMY BY IMPLICATION / NO LANE OPENED.**

## 14. Semantic summary

TORMENT is **automatic-first**: it acts only when triggered from outside (input, invocation, bounded event),
and that reactive posture is treated as sufficient. **Autonomy** — starting work with no triggering input
(self-generation, scheduling, background watching, idle navigation, unsolicited interaction, any
perception-to-action loop) — is **not the default, never implied, and not opened**; it may only be
considered later as an explicit, operator-owned, Codex-gated mode ladder above **Mode 0**, which is
reaffirmed as the current ceiling. The doctrine holds the automatic/autonomous line across every other
surface: embodiment tunnels and body-liveness are presentation not autonomy (tunnel permission ≠ loop
permission); an external model call grants no live loop; dreaming stays externally triggered and
inert-candidate-producing, never self-starting; MCP stays reactive; and no durable-write, output, identity,
or substrate authority is granted. **Decision framing only — opens no implementation lane.**

*End — Automatic-First / Autonomy Ceiling Doctrine v0.1. Docs-only, decision framing, non-authorizing. Opens
no implementation lane.*
